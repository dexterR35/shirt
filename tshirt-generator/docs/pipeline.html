T-SHIRT GENERATOR · IMAGE PROCESSING

From the base photo to the download

The shirt photo (base.png) is never traced or redrawn. Each kit is validated SVG paint that is multiplied into the photo's pixels, so the fabric folds, highlights and transparent edges stay exactly as photographed. The preview, the catalog thumbnails and every download use the same composite. This page covers image processing only, not research or the catalog UI.

What “200 × 200 units” means

It's a drawing grid, not a pixel size. All kit paint (sleeves, stripes, collar) is drawn on a 200 × 200 square that covers the shirt: the shirt runs from about unit 2 at the collar to unit 198 at the hem. At render time the square is scaled to 7/8 of the image (a 1/16 margin on each side), so the same paint fits every size exactly.

Sizes and where their pixels come from

The base is chosen by the square render size, which is the shorter side of the download. A 4096 × 2304 (16:9) download renders a 2304 square from the 8K master; a 2048 × 1152 one renders an 1152 square from the WebP copy.

Why quality is kept

  • Never enlarged. Every size, including 4096, scales the photo down, so no detail is invented.
  • Lossless where it counts. The master PNG, the lossless WebP screen copy, PNG downloads and WebP at quality 1 (VP8L).
  • The fabric isn't redrawn. Shading and edges come straight from the photo; only the color is multiplied in.
  • Paint is vector. The SVG paint is rasterized fresh at each size, so stripes and trims stay crisp.
  • No substitutes. A variant that isn't ready renders the plain photo; another kit is never shown in its place.
  • AVIF is visually lossless, not bit-exact. Quality 95, full color resolution (4:4:4) and exact transparency: about 52 dB against the PNG, roughly a tenth of the size.
  • The page never waits. Decoding, compositing and encoding run in two workers (screen and download), so a long ZIP never delays the preview.
  • A ZIP doesn't recompress. Images are stored as they are.

Where it lives in the code

  • scripts/prepare-png-base.mjs: hash check, master copy and the 2048 WebP crop
  • vite.config.js: preloads the 2048 WebP
  • src/lib/kit-config.js, png-layout.js: load and validate a kit's paint config
  • src/lib/kit-edit.js: applyEdits for color edits
  • src/lib/png-shirt.js: base mapping and renderColorArtwork (paint SVG)
  • src/lib/png-collar.js: collar bands inside the existing neckline
  • src/lib/png-preview.js: SVG rasterizing, base choice, render cache, the two worker lanes
  • src/lib/render.worker.js: base decode, composite, PNG/WebP/AVIF encoding
  • src/lib/composite.js: paintArea and compositePixels, shared by page and worker
  • src/lib/export.js: sizes, shapes, formats, file names, ZIP
  • src/App.jsx: yes/no question and batch downloads
